BOUND 0.10.0 is the first release with ready-made downloads: unzip and run, no building from source.
It runs the **testnet**, whose coins have no value. Mainnet hasn't launched yet: `--mainnet` runs a
preview chain that will be thrown away ([the road to mainnet](https://github.com/Sonic-Bound/Bound/blob/main/docs/mainnet-roadmap.md)).

## Downloads

| File | For |
|---|---|
| `bound-0.10.0-win64.zip` | Windows 10 or 11, 64-bit: the wallet app (`bound-qt.exe`) and the command-line programs, with everything they need |
| `bound-0.10.0-x86_64-linux-gnu.tar.gz` | Linux x86-64 with glibc 2.35 or newer (Ubuntu 22.04, Debian 12, Fedora 36 or later): `boundd`, `bound-cli`, `bound-explorer`, `bound-seeder`, systemd units and `bound-server`. No wallet app for Linux yet: build it from source |
| `bound-0.10.0-aarch64-linux-gnu.tar.gz` | the same for 64-bit ARM with glibc 2.39 or newer: ARM cloud servers (Oracle, AWS), a Raspberry Pi 4 or 5 on Raspberry Pi OS 13 or Ubuntu 24.04 |
| `SHA256SUMS` | the SHA-256 of each file |

**Windows:** unzip, then double-click `bound-qt.exe`. The programs aren't code-signed yet, so Windows
may say *"Windows protected your PC"*: check the download (below), then choose *More info* and
*Run anyway*.

**Linux:** unpack, then `bin/boundd node`. Nothing else to install: the libraries are built in.

## Check the download

Compare the file's SHA-256 with `SHA256SUMS` (`Get-FileHash <file>` on Windows,
`sha256sum --ignore-missing -c SHA256SUMS` on Linux). GitHub also attests every file, which proves
it was built by this repository's release workflow from the `v0.10.0` tag and hasn't been changed
since. With the [GitHub CLI](https://cli.github.com):

    gh attestation verify bound-0.10.0-win64.zip --repo Sonic-Bound/Bound

## What's new since 0.9.0

- **Three networks** in every program: `--testnet` (the default), `--regtest` (a private chain for
  testing, mined instantly) and `--mainnet` (a preview), each with its own data directory.
- **Mainnet's rules are settled:** Bitcoin's schedule (10-minute blocks, 50 BOUND halving every
  210,000 blocks, no premine), ASERT difficulty adjusted every block, addresses starting with `B`.
- **A faster miner:** about twice as fast per thread, and it uses every core but one. Set the number
  of threads on the wallet app's Mining page, with `--minethreads`, or with `setmining`'s third
  parameter.
- **Hardening:** every push is now tested under AddressSanitizer, UndefinedBehaviorSanitizer and
  ThreadSanitizer, and everything that reads outside input is fuzzed. It found one bug, now fixed:
  an empty database key handed LevelDB a null pointer.
- **`--version`** on every program; on Windows, each `.exe` shows its version under
  *Properties > Details*.
- **Running a server is one command per job** with `bound-server` (in the Linux packages):
  install and upgrade, a node, the explorer behind HTTPS, a DNS seeder, health reports. See
  [running a server](https://github.com/Sonic-Bound/Bound/blob/main/docs/running-a-server.md).
- **The explorer has `/health`** for uptime monitors, and a DNS seeder can start crawling from the
  node on its own machine (`--node 127.0.0.1`).
- **The systemd units are per network:** `boundd@testnet`, and `boundd@mainnet` on launch day.
  `bound-server install` moves a server running the old `boundd.service` across, keeping its chain.

## Upgrading

Stop the old node or wallet app, then start the new one. The chain, the wallet and the settings stay
where they were (`%APPDATA%\BOUND\testnet`, `~/.bound/testnet`). The testnet's rules haven't
changed, so 0.9.0 and 0.10.0 nodes keep talking to each other.
